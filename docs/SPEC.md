# SPEC — 清单 · 记账 · 健康

> 本文档描述产品的本质特征与最终形态,依据 `prototype/` 高保真动态原型整理。
> 原型右侧的 Tweaks 调参面板为原型探索工具,**不纳入产品**;其默认值固化为本规格的设计常量。

## 1. 产品定位

移动优先的个人生活管理单页应用(SPA),包含三个独立模块:

| 模块 | 一句话描述 |
|---|---|
| 待办(Todo) | 带时间生命周期的任务清单:未开始 → 进行中 → 已过期/已完成 |
| 支出(Expense) | 分类 → 明细两级记账,甜甜圈饼图呈现占比 |
| 健康(Health) | 体重 / 血压测量记录,基于个人资料推导理想区间并三态预警 |

- **无后端**:纯前端运行,所有数据持久化于浏览器 localStorage。
- **单用户**:无登录、无账户体系。
- 首次启动预置演示种子数据(见 §7.3),此后以用户数据为准。

## 2. 整体形态

### 2.1 布局与导航

- 手机壳布局:内容区 `min(430px, 100vw) × min(880px, 100vh)` 居中;视口足够大时(≥480×920)显示 36px 圆角与投影,小屏铺满。
- 底部 Tab 栏固定三项:**待办 / 支出 / 健康**,线性图标 + 文字,当前项高亮。
- 应用记住上次所在 Tab(localStorage 键 `tdex-tab`),刷新后恢复。
- 内容区独立纵向滚动(`overscroll-behavior: contain`)。

### 2.2 设计语言(固化常量)

- 色彩全部使用 **oklch** 表达;暖白纸质底色体系:
  `--paper: oklch(0.978 0.008 85)`、`--paper-deep: oklch(0.955 0.012 85)`、`--ink: oklch(0.28 0.015 60)` 及 soft/faint 层级。
- 点缀色:`--accent-hue: 70`(暖橙),`--accent: oklch(0.72 0.13 70)` 及 ink/soft 派生。
- 卡片圆角 `--radius: 18px`;密度为「舒适」档;危险色 `--danger: oklch(0.58 0.17 25)`。
- 字体栈:`"Outfit", "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", sans-serif`。
- 分类配色由色相(hue)统一派生:卡底 `oklch(0.95 0.035 h)`、深卡底 `oklch(0.92 0.055 h)`、文字 `oklch(0.42 0.09 h)`、扇区 `oklch(0.78 0.11 h)`(hover `0.72 0.14`)。

## 3. 待办模块

### 3.1 数据模型

```ts
Task = { id, cat, text, createdAt, startAt, dueAt, done: boolean }
```

四个固定分类(单字图标 + 色相):工作(工/55)、生活(生/25)、学习(学/260)、健康(健/155)。

### 3.2 状态生命周期(由当前时间推导,非存储字段)

| 状态 | 判定 | 颜色语义 |
|---|---|---|
| done | `done === true` | 灰,标题加删除线 |
| upcoming 未开始 | `now < startAt` | 绿 |
| active 进行中 | `startAt ≤ now ≤ dueAt` | 黄 |
| overdue 已过期 | `now > dueAt` | 红 |

- 页面每 **30 秒**刷新一次当前时间,状态与文案随之自动迁移。
- 卡片顶部进度条表示**当前阶段剩余时间比例**(1→0):upcoming 取 `createdAt→startAt` 区间,active 取 `startAt→dueAt` 区间;overdue/done 不显示进度条。
- 状态副标题:`X后开始` / `剩余 X` / `已逾期 X` / `已完成`;时长格式化规则:<60 分钟显示分钟,<24 小时显示「N 小时 M 分」,否则「N 天 M 小时」。

### 3.3 页面行为

- 头部:标题「今日待办」+ 副标题「还有 N 件事要做」(全部完成时显示「全部完成,休息一下吧」);右上角 ＋ 新建按钮。
- 图例:未开始(绿)/ 进行中(黄)/ 已过期(红)。
- 排序:active → overdue → upcoming → done,同组内按 `dueAt` 升序。
- **FLIP 重排动画**:状态变化引起位置交换时,下移卡片中段放大(1.06)、上移卡片缩小(0.95),同时到达;新插入卡片淡入放大。
- 复选框点击:先缩后弹的脉冲动画,切换 done 状态。
- 点击卡片(非批量模式)打开编辑对话框;支持键盘 Enter/Space 触发。

### 3.4 新建 / 编辑对话框

- 字段:分类(TypePicker,见 §6.3)、描述(必填,≤40 字)、开始日期(date)、时间范围(开始/结束 time)。
- 结束时间不晚于开始时间时视为**跨夜**,自动 +24h。
- 编辑模式回填原值,保存按钮文案为「保存」;新建为「添加」。表单非法时提交按钮禁用。

## 4. 支出模块

### 4.1 数据模型

```ts
ExpenseTag  = { id, label, glyph, hue, items: ExpenseItem[] }
ExpenseItem = { name, amount, date: string }   // date 为展示字符串,如 "6.05"、"6.02 – 6.10"、"本月累计"
```

预置五个分类:饮食(食/40)、交通(行/230)、居住(住/150)、娱乐(娱/320)、购物(购/280)。

### 4.2 甜甜圈饼图(总览与明细共用)

- SVG 环形图(300×300,外径 118 / 内径 64,扇区间隙 1.6°),中心显示标题与总金额。
- **点击整图放大/还原**(缩放态切换),底部提示文案随之变化。
- **hover / 触摸滑动**:扇区沿中线向外摘出 10px、加深填色,并跟随指针显示浮动 tooltip(分类名、百分比、金额)。
- 触控策略:轻点不阻止默认(保留 click 放大);滑动 `touchmove` 阻止页面滚动并用 `elementFromPoint` 追踪扇区;离手即收起 tooltip。
- 明细页扇区色相按 `(tag.hue + i × 16) % 360` 派生。

### 4.3 两级页面

- **总览页**:标题「本月支出」+ 日期范围副标题;大饼(中心为总支出);分类卡片列表——单字图标、分类名、「N 笔开销」、金额、占总支出百分比、右箭头;点击进入明细页。所有分类删空后隐藏 ＋ 按钮。
- **明细页**:返回键 + 「{分类}支出」标题 + 「占总支出 X% · 共 N 笔」副标题;该分类饼图(中心为分类小计);逐笔卡片(名称、日期、金额、占分类百分比),配色比总览浅一档;点击单笔卡片进入编辑。

### 4.4 记一笔 / 编辑对话框

- 字段:分类(TypePicker)、描述(必填,≤20 字)、金额(>0,两位小数)、日期(date,存储为 `M.DD` 字符串)。
- 明细页发起时默认选中当前分类。
- 编辑可**跨分类移动**:同分类原位替换;换分类则从原分类移除并追加到新分类。
- 编辑时若未改动日期控件,保留原始日期字符串(区间型日期如 "6.02 – 6.10" 不被覆盖)。

## 5. 健康模块

### 5.1 数据模型

```ts
Profile      = { gender: 'male'|'female', age, height, weight }   // 默认 { male, 28, 175, 68 }
HealthRecord = { id, metric: 'weight'|'bp', ts, value, dia? }     // weight: value=kg;bp: value=收缩压, dia=舒张压
```

两个指标:体重(重/200/kg)、血压(压/10/mmHg)。

### 5.2 理想区间与三态判定

- 体重理想区间:BMI 18.5–23.9 × 身高² 。
- 收缩压:下限 90;上限按年龄分档 <45 → 120、45–59 → 130、≥60 → 140。
- 舒张压:下限 60;上限同理 80 / 85 / 90。
- 三态:**bad** = 超出区间;**warn** = 距任一边界不足区间宽度的 **20%**(固化阈值);**good** = 其余。
- 血压记录整体状态取收缩/舒张中较差者;状态文案:理想 / 偏高 / 偏低 / 接近上限 / 接近下限,血压细化为「收缩压偏高」「舒张压接近上限」等。
- 状态色:good 绿(hue 152)、warn 黄(85)、bad 红(25)。

### 5.3 个人资料

- 齿轮按钮打开资料对话框:性别(男/女分段按钮)、年龄(1–120)、身高(80–250cm)、体重(20–300kg);越界禁止保存。
- 资料持久化于 localStorage 键 `tdex-profile`,损坏数据自动回退默认值。
- 修改资料后理想区间、图表节点状态、记录状态即时重算。

### 5.4 趋势折线图

- 近 30 天**日均值**节点(同日多次测量取均值,体重保留 1 位小数、血压取整),折线连接,节点按三态着色。
- 理想区间上下限两条虚线及数值标签(血压图基于收缩压区间);Y 轴自适应包含区间与数据并留白。
- 右上角体重/血压**卡片式切换**。
- 指针移动 / 触摸滑动:横向吸附最近节点,显示数据框——日期+测量次数、均值(血压为 `收缩/舒张`)、较前一日差值与百分比(首个记录日特殊文案)、当前状态、理想区间;离手/移出即收起。
- 触控策略同 §4.2(轻点保留,滑动阻止滚动)。

### 5.5 测量记录列表

- 倒序(新→旧)分页展示,**每页 5 条**;Pager 为左右箭头 + 最多 3 个页码按钮,翻页时收起展开项。
- 记录卡:指标图标、名称+数值(体重 `X.X kg`;血压 `sys / dia mmHg`)、日期+星期、三态状态胶囊。
- 点击展开详情:测量时间(M月D日 星期 HH:mm);体重补充 BMI 与理想区间;血压补充收缩/舒张与双区间。

### 5.6 新增数据对话框

- TypePicker 选择体重/血压;体重单栏(>0,0.1 步进);血压双栏(收缩、舒张均 >0 且**收缩 > 舒张**);日期 + 时间(默认当前)。
- 新增后:插入记录并按时间倒序排列、图表自动切到该指标、记录列表回到第一页。

## 6. 通用交互

### 6.1 批量删除(三个模块统一)

适用对象:待办卡、支出分类卡、支出明细卡、健康记录卡。

1. **长按 500ms** 进入批量模式(指针位移 >9px 或松手则取消;触发后吞掉随后的 click;屏蔽右键菜单),长按的卡片自动入选。
2. 模式中所有卡片**抖动**(相位按索引错开),右侧出现红叉选择钮:空心=未选,红底白叉=已选;卡片原有点击行为禁用。
3. 右上角 ＋ 按钮替换为红色**垃圾桶 + 选中计数**。
4. 点垃圾桶弹出确认对话框:「确定要删除选中的 N {条待办/个分类/笔开销/条记录}吗?删除后无法恢复。」——「是,删除」执行并退出模式;「否」维持模式。
5. 取消所有选中(集合清空)时自动退出批量模式。

### 6.2 模态对话框

居中卡片 + 毛玻璃遮罩;点击遮罩空白处关闭;底部「取消(ghost)/ 主操作(primary,非法时禁用)」双按钮。

### 6.3 TypePicker 类型选择器

对话框左侧纵向组件:大圆显示当前选中类型(图标+名称,类型色相配色),下方一排小圆点切换;待办分类、支出分类、健康指标共用。

## 7. 数据与持久化

### 7.1 技术形态

- 状态管理:**Zustand**,每模块一个 store(`features/*/store.ts`),通过 **persist 中间件**写入 localStorage。
- 跨模块共享的派生逻辑(状态推导、区间计算、格式化)为纯函数,与 store 解耦。

### 7.2 localStorage 键约定

| 键 | 内容 |
|---|---|
| `tdex-tab` | 上次所在 Tab id |
| `tdex-profile` | 健康个人资料 |
| `tdex-todo` | 待办 store(tasks) |
| `tdex-expense` | 支出 store(tags) |
| `tdex-health` | 健康 store(records) |

读取损坏/缺失数据时回退默认值,不抛错。

### 7.3 首启种子数据

首次启动(对应键不存在)时写入演示数据,之后完全以用户数据为准:

- 待办:7 条覆盖四分类与全部四种状态,时间相对首启时刻生成。
- 支出:五分类共 17 笔明细(原型 `EXPENSE_TAGS` 全量)。
- 健康:**确定性伪随机生成器**(线性同余,固定种子)生成近 30 天体重/血压记录,锚定首启当日 0 点,保证同一天内生成结果可复现。

## 8. 非功能要求

- **依赖方向**:`app → pages → features → shared`,由 ESLint boundaries 强制。
- **TypeScript strict**,零 lint 错误(husky pre-commit 已接入)。
- **可访问性**:延续原型的 aria-label / role / aria-expanded / aria-selected;卡片支持键盘 Enter/Space;图表带 `role="img"` 与描述。
- **触控适配**:饼图与折线图按「轻点放行、滑动拦截」策略处理 touch 事件(passive 配置见 §4.2)。
- **测试**:单元 + 集成 + E2E(Playwright)三层齐备,覆盖率 ≥80%;纯函数(状态推导、区间计算、格式化、几何计算)100% 单测覆盖。
- 文件组织:按 feature 拆分,单文件 200–400 行为宜,不超过 800 行;状态更新一律不可变(immutable)。
